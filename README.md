# ScrollBurn 🌍🔥

ScrollBurn is an eco-designed awareness platform that allows young users to log their daily social media usage (TikTok, Instagram, YouTube, Snapchat, etc.) and visualize the equivalent CO₂ carbon footprint generated by their "doom scrolling" habits. The website itself is extremely lightweight and eco-designed — this intentional paradox is the core narrative of the project.

**Tagline:** *"You scroll. The planet burns. Let's see how much."*

## 🛠️ Tech Stack & Green IT Justifications
- **Frontend**: Vanilla HTML5, CSS3, JavaScript (0 framework overhead).
  - *Green IT*: No framework means 0 KB of unused code loaded.
  - *Green IT*: Dark mode default reduces OLED screen energy consumption by up to 60%.
  - *Green IT*: Using `system-ui` font avoids 1 external HTTP request per font weight.
- **Backend**: Python with Flask
  - *Green IT*: Flask is a micro-framework that uses minimal CPU and memory compared to heavier alternatives like Django.
- **Database**: SQLite (Development) & PostgreSQL (Production)
  - *Green IT*: SQLite for dev requires no dedicated server process, meaning 0 additional energy consumption locally.
- **Security**: bcrypt and PyJWT
  - *Green IT*: Bcrypt provides robust security without needing external API calls to authentication providers.

## 🚀 Installation & Local Execution

1. **Clone the repository:**
   ```bash
   git clone https://github.com/your-username/scrollburn.git
   cd scrollburn
   ```

2. **Set up the virtual environment & install dependencies:**
   ```bash
   python3 -m venv venv
   source venv/bin/activate
   pip install -r requirements.txt
   ```

3. **Configure environment variables:**
   ```bash
   cp .env.example .env
   ```
   *(Ensure `.env` contains your `DATABASE_URL` and `SECRET_KEY`)*

4. **Initialize Database (Optional if Flask SQLAlchemy handles it):**
   ```bash
   sqlite3 scrollburn.db < database/init.sql
   ```

5. **Run the Flask Development Server:**
   ```bash
   cd backend
   flask run
   # Or run directly: python app.py
   ```
   The application will be accessible at `http://localhost:5000`.

## 🌱 Git & Branching Strategy
We adhere to a strict branching strategy to avoid working directly on `main` and to facilitate code reviews:
- **`main`**: The stable, production-ready branch.
- **`dev-front`**: Dedicated branch for user interface and frontend components.
- **`dev-back`**: Dedicated branch for server logic, routing, and APIs.
- **`database`**: Dedicated branch for data structure, schema updates, and access.
- **`feature/*`**: Short-lived branches for specific tasks (e.g., `feature/auth`, `feature/homepage`).

**Commit Convention (Descriptive & Readable):**
- `feat:` A new feature
- `fix:` A bug fix
- `docs:` Documentation only changes
- `refactor:` A code change that neither fixes a bug nor adds a feature
